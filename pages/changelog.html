v1.4.5（2026-09-23 · 修复：上传了新版、浏览器却还是旧版本）

缓存链路加固：全量资源版本化 + Service Worker 直连更新 + 版本探针提示 + 「打开的是旧版本？」自助页

  • 🧊 全量资源版本化（治本）：此前只有 7 个脚本带 ?v=，全站 1199 处本地资源引用里 只有 151 处带版本参数——style.css（142 页）、theme.js、ux.js、nav.js、breadcrumb.js、sop-data.js 等全都不带。于是浏览器 HTTP 缓存和 Service Worker 的 cache-first 会把旧 CSS / 旧脚本留着，出现「HTML 是新的、样式脚本还是旧的」。现在 所有本地 CSS / JS 引用都带 ?v=版本号，版本一升级就是新 URL，直接绕过旧缓存；sw.js 预缓存清单同步写同一参数，避免离线时 URL 对不上。
  • 📡 Service Worker 更新策略加固：① 页面导航请求改为 no-store 直连网络——GitHub Pages 给 HTML 的 max-age=600 会让刚上传的新页面最多晚 10 分钟才出现；② 每次打开页面都主动调一次 registration.update()（浏览器默认可能隔 24 小时才查新版本）；③ 新 Worker 装上即接管（skipWaiting + clients.claim），旧缓存自动删除；④ 新增 SKIP_WAITING 消息通道。
  • 🔔 版本探针 + 更新提示条：新增 version.json（永不缓存，由发布脚本生成）与每页 head 的 <meta name="site-version"> 标记。页面打开时会比对「本页版本 vs 线上最新版本」，不一致就在底部弹出提示条：「线上已更新到 vX.Y.Z，你打开的是 vY.Y.Y —— 点此立即更新」，按钮会清除本站缓存、注销旧 Service Worker 并带时间戳重新加载；提示条里还有「还是旧的？」入口。
  • 🆕 新增自助页「打开的是旧版本？」（cache-help.html）：① 一键清除缓存并重新加载（内联脚本实现，即使旧脚本被缓存也照样能用，且不会动学习进度 / 笔记）；② 讲清四层缓存——浏览器 HTTP 缓存 / Service Worker 缓存 / GitHub Pages CDN（HTML 约 10 分钟）/ 已安装 PWA 外壳与微信内置浏览器；③ 各平台强制刷新步骤（Windows / macOS / Android / iOS / PWA / 微信）；④ 五个常见问题（含「清缓存会不会丢笔记」「为何没弹提示条」「推送后多久生效」）；⑤ 维护者视角列出本站已做的加固与 GitHub Pages 无法自定义响应头这一平台限制。
  • 🛠 发布与校验流程升级：scripts/release.js 现在一次到位——中英文页脚版本、页脚「内容核对 YYYY-MM」、head 的 site-version 标记、sw.js 缓存名、导出文本版本、changelog meta 版本号、全站所有 assets/**/*.css|js 的 ?v=（HTML 与 sw.js 双向同步）、version.json。scripts/check-structure.js 对应加上缓存一致性闸门：任何资源漏 ?v=、参数不是当前版本、带了参数却没进 sw.js 预缓存清单、缺 site-version 标记、version.json 与版本 / 月份不一致，都会 FAIL 拦下来。
