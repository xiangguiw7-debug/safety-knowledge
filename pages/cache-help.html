首页 / 资源 / 旧版本问题

打开的是旧版本？

正常情况下不需要你做任何操作：本站现在会在打开页面时自动比对线上版本，发现更新会自动清一次缓存并重新加载；只有极少数顽固场景（已安装的 PWA、微信内置浏览器）才需要手动处理。

🤖 本站的自动更新（默认已开启）

  • 页面导航直连网络：每次打开页面都绕过浏览器 HTTP 缓存去取最新 HTML（防止“刚发布的新页面看不到”）。
  • 每次打开都查一次新版本：主动检查 sw.js 与 version.json（这个探针文件永不缓存）。
  • 发现线上版本更高 → 自动更新：如果你刚打开页面、还没开始滚动或点击，本站会自动清一次自身缓存并重新加载，你什么都不用按。若你已经在阅读或操作，则改为底部弹条提示，点一下即可（不打断你）。
  • 资源带版本号：所有 CSS / JS 引用都带 ?v=版本，新版本 = 新地址，不会再出现“HTML 是新的、样式脚本是旧的”。

也就是说：普通刷新（甚至什么都不做）就应该看到最新版。下面的一键修复与手动步骤只用于兜底。

🧹 一键修复（先试这个）

按钮会做三件事：删掉本站的 Service Worker 缓存 → 注销 Service Worker → 带上时间戳重新打开当前页。它只清缓存，不会动你的学习进度、笔记与错题本（那些存在 localStorage，和缓存是两套东西）。

🔍 为什么会出现「上传了新版，打开还是旧的」

从服务器到你的屏幕之间，一共可能有 四层缓存在起作用。任何一层留着旧副本，你就会看到旧版本——所以「文件传上去了」和「你看到新版」不是同一件事。

层级它缓存什么能保持多久本站的应对
1. 浏览器 HTTP 缓存 CSS、JS、图片等静态文件 按服务器响应头；GitHub Pages 给静态资源的策略是 10 分钟，但已缓存的 URL 会被反复复用 所有本地 CSS / JS 引用统一带 ?v=版本号，版本一升级就是新 URL，直接绕过旧缓存
2. Service Worker 缓存（PWA） 整站页面与脚本（离线可用的那套） 直到缓存版本号变化；旧 Worker 还可能继续接管页面 缓存名带版本、新 Worker 立即接管（skipWaiting），导航请求直连网络不再走缓存
3. GitHub Pages 的 CDN HTML 与静态资源 约 10 分钟（该平台不允许自定义响应头） 页面导航请求绕过 HTTP 缓存直连；极端情况下最多晚 10 分钟
4. PWA 外壳 / 微信等内置浏览器 整个应用的独立副本 / 内核自己的缓存 可能很久，应用不彻底关闭就一直用旧副本 页面上出现「发现新版本」提示条；实在不行按下面的手动步骤

另外还有一种情况：缓存没问题，但你没看到变化——如果这次更新只是改了文字或微调数值，页面看起来确实和上一版一样。想确认版本，看页脚「版本 v…」那一行，或本站 更新日志。

🛠 各平台手动强制刷新

电脑（Windows / Linux）

  1. Ctrl + F5，或 Ctrl + Shift + R（强制重新下载）；
  2. 还不行：按 F12 打开开发者工具 → Network 面板 → 勾选 Disable cache → 保持面板打开再刷新一次；
  3. 再不行：站点设置（地址栏左侧图标）→ 清除 Cookie 和网站数据 → 刷新。

电脑（macOS）：Cmd + Shift + R；Safari 需先在「设置 → 高级」里打开开发菜单，再用 Option + Cmd + E 清空缓存。

Android（Chrome / Edge）：⋮ 菜单 → 历史记录 → 清除浏览数据 → 勾「缓存的图片和文件」；或长按地址栏域名 → 站点设置 → 清除并重置。只想针对本站清，用后者更安全。

iPhone / iPad（Safari）：设置 → Safari → 高级 → 网站数据 → 找到本站 → 删除；或设置 → Safari → 清除历史记录与网站数据（会清所有站点，先确认别处没有要保留的登录态）。

已安装的 PWA（添加到主屏幕的应用）：先彻底关闭应用（多任务界面划掉，不是切到后台）再打开；仍不行就卸载图标，重新用浏览器打开本站后「添加到主屏幕」。Android 还可在 应用信息 → 存储 → 清除缓存。

微信 / QQ 等内置浏览器：右上角 ⋯ → 刷新；顽固的话在「我 → 设置 → 通用 → 存储空间 → 清理缓存」，或点右上角 ⋯ → 在浏览器中打开。

快速判断是不是缓存问题：用无痕窗口（Ctrl / Cmd + Shift + N）打开本站。无痕里是新版、普通窗口是旧版 → 100% 是缓存，按本页一键修复即可。

📌 常见问题

清除缓存会不会把我的学习进度、笔记清掉？

本页的一键修复不会。学习进度、知识卡笔记、错题本、主题设置保存在 localStorage，与缓存是两套存储。但浏览器里「清除浏览数据 / 清除网站数据」这类操作会连 localStorage 一起清掉——所以建议先到 数据备份 页导出一次，或复制同步文本存一份。

页面上为什么没有出现「发现新版本」提示条？

三种可能：① 你已经是最新版；② 离线或网络拦截了版本探针（version.json）请求，此时会静默跳过，不影响浏览；③ 你打开的是很旧的缓存页面，那时还没有这个机制——手动强刷一次之后，以后就会自动提示了。

提示条出现了，点了「清除缓存并更新」还是旧的？

说明卡住的是更外层的缓存（PWA 外壳或内置浏览器内核）。彻底关闭应用再打开，或按上面的平台步骤处理；这种情况下版本探针会在你每次打开时再提示一次，不会静默变旧。

推送更新后，别人多久能看到新版？

正常情况：刷新一次即可（资源带版本号、页面导航直连网络）。最坏情况：受 GitHub Pages 的 10 分钟 CDN 缓存影响，可能晚约 10 分钟；已安装 PWA 的用户需要重新打开应用，届时会看到更新提示条。

怎么一眼确认自己看的是哪一版？

每个页面页脚都有「版本 vX.Y.Z · 内容核对 YYYY-MM」，本页顶部也会显示当前页面版本与线上最新版本。对不上就按上面清一次缓存。

⚙️ 维护者：本站已经做了哪些加固

  • 全量资源版本化：142 个页面的所有本地 CSS / JS 引用都带 ?v=版本号，发布脚本会自动刷新；sw.js 的预缓存清单同步写同一个参数，避免「HTML 是新的、脚本还是旧的」。
  • Service Worker 策略：页面导航请求 no-store 直连网络；缓存名带版本号，新版本装上即接管（skipWaiting + clients.claim），旧缓存自动删除。
  • 版本探针：version.json 永不缓存，配合每页 head 里的 site-version 标记比对，发现线上更新就弹提示条，并提供一键清除缓存。
  • 回归闸门：node scripts/check-structure.js 会拦住版本 / 日期 / 资源参数不一致（页脚、sw.js、HTML 三方比对）。
  • 服务端限制：GitHub Pages 不允许自定义响应头（HTML 固定约 10 分钟缓存）。若要秒级生效，需要换 Cloudflare Pages / Netlify / Vercel，或在前面临时加一层可控 CDN。
